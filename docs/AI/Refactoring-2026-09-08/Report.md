# 리팩토링 점검 및 변경 기록

## 적용한 변경

7개 스크립트의 변경을 완료했다. 게임 규칙과 엔딩 문구, 씬 연결용 필드 및 콜백 이름은 유지했다.

| 파일 | 변경과 목적 |
| --- | --- |
| ChangeScene.cs | 양측 의견 선택의 공통 상태 변경을 ApplyOpinion으로 묶어 자원·선택 기록 처리의 중복을 줄였다. |
| HowMany.cs | 선택 배열 길이를 기준으로 남은 사건을 센다. |
| Status_Image.cs | 자원 값이 바뀔 때만 아이콘을 갱신한다. 경고 감시는 계속 수행한다. |
| Load/MainStory_Load.cs | 첫 Update에서 화면을 한 번 표시한 뒤 해당 표시 컴포넌트를 비활성화한다. |
| Load/Opinion_Load.cs | 첫 Update에서 사건과 비용을 한 번 표시한다. |
| Load/Scrolls_Load.cs | 첫 Update에서 목록을 한 번 표시하고 완료 이미지를 한 번만 로드한다. |
| Load/News_Load.cs | 시작과 페이지 이동에서만 내용을 갱신한다. 사건이 없는 경우 씬 전환 후 즉시 반환하고 빈 목록 접근도 차단한다. |

첫 화면 갱신을 Update에 둔 이유는 기존처럼 모든 Start 실행 뒤 데이터를 읽기 위해서다. 이후 세 표시 컴포넌트는 다음 씬 로드까지 같은 내용을 표시한다. 씬 이동과 상태 변경은 별도의 컴포넌트가 담당한다.

## 검증

- 수정 전과 수정 후에 설치된 Unity 6000.5.8f1의 Roslyn 컴파일러로 `Assembly-CSharp`를 컴파일했다. 기존 Unity 응답 파일 `Library/Bee/artifacts/2000b0aEDbg.dag/Assembly-CSharp.rsp`을 사용하고 출력은 `Temp/RefactorValidation`에 분리했다.
- 두 컴파일 모두 오류 없이 완료했다. `GameManager.cs`의 `FindObjectOfType` 사용에 대한 기존 CS0618 경고 1개가 남아 있다.
- 원본과 비교해 변경 파일의 public/직렬화 필드 선언, public 메서드 시그니처, 한글 문자열 리터럴이 보존됐음을 확인했다.
- .NET 생성 프로젝트 빌드는 처음에 SDK 경로 권한, 이후 NuGet assets 파일 부재로 실패했다. 최종 컴파일 검증은 위 Unity Roslyn 경로로 수행했다.
- Unity Editor 실행, Play Mode, 실제 버튼 동작, 시각적 결과, WebGL 빌드는 직접 검증하지 않았다. 사용자가 진행한 빌드의 결과를 이 검증에 포함하지 않았다.
- 상태: 코드 및 호환성 정적 검증 통과, 런타임 검증 미완료.

## 점검에서 남은 후보

전체 검토는 소스 수준의 점검이며 아래 항목은 재현된 런타임 결함과 구분한다.

| 우선순위 | 관찰·확신 | 다음 작업 |
| --- | --- | --- |
| 중간 | GameManager.Status는 호출할 때마다 지지도를 더한다. 코드로 확인됨. 정상 UI 경로에서 중복 호출되는지는 미확인. | 연말 정산을 한 번만 적용하도록 상태 전이를 설계하고 재호출 테스트를 추가한다. |
| 중간 | SetNewYear는 사건 재추첨을 반복하며 후보 부족 시 종료 경로가 없다. 코드로 확인됨. 정상 9년 흐름에서 후보 부족 발생은 미확인. | 연도 범위 및 데이터 개수 검증과 후보 목록 기반 추첨을 검토한다. |
| 중간 | 데이터와 이미지 연결이 리스트 순서에 의존한다. 코드로 확인됨. | 데이터 교체 전에 안정적인 ID 연결과 누락 검증을 마련한다. |
| 낮음 | Character는 Start에서 정한 스프라이트를 매 프레임 재지정한다. 코드로 확인됨. | 애니메이션 등 다른 작성자의 존재를 확인한 후 최초 갱신으로 축소한다. |
| 낮음 | ShowResult는 긴 문구와 계산·표시를 한 클래스에 포함한다. 유지보수 관찰. | 엔딩 경계값 테스트를 먼저 확보하고 계산과 표시를 분리한다. |

기존 프로젝트는 규모가 작고 생성 데이터 코드가 분리되어 있어 대규모 아키텍처 교체보다 위와 같은 국소 변경이 적합하다.

## 런타임 확인 절차

1. Main에서 시작해 Scrolls → Opinion으로 이동하고 양측 선택의 자원 소모와 완료 표시를 확인한다.
2. 자원이 부족한 선택은 경고만 표시하고 상태가 유지되는지 확인한다.
3. 뉴스의 첫 페이지, 이전/다음 페이지와 양끝 경계를 확인한다.
4. 아무 사건도 처리하지 않고 진행해 메인 스토리로 이동하는지 확인한다.
5. 다음 해와 재시작에서 사건 목록, 자원 아이콘, 스토리 화면이 다시 갱신되는지 확인한다.

## 원본 보관

작업 시작 전 스크립트는 이 폴더의 `before/Scripts`에 보관했다. Unity가 지울 수 있는 Temp 외부의 백업이다. 다른 수정이 생긴 뒤에는 전체 복원하지 말고 파일별로 비교한다.
